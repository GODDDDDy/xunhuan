# 第39项：G6的Adam状态保留/重启——1000步匹配诊断

2026-10-19，用户明确要求开始训练。探索性诊断，不是正式完整恢复实验。

## 集中实验卡

|要素|固定设置|
|---|---|
|唯一问题|同一强G6权重继续优化时，继承原Adam状态相对于清空Adam，是否有助于短程整图能力保持？|
|归属|恢复训练的能力保持；不评价增强、循环或H/C|

## 判据及结论边界（固定，非显著性检验）

主要判断只使用1000步64图，不依据16图挑选终点。

- KEEP−RESET场景PSNR≥+.10dB、SSIM≥0、至少6/8场景PSNR正，且KEEP−G6≥−.05dB/SSIM≥−.0002、RESET−G6≤−.10dB：支持本短程设置下保留Adam有实际能力保持作用。
- 两组相对G6均≤−.10dB：继承Adam不足以避免当前训练的退化；不等于Adam没有任何影响。
- RESET反向优于KEEP达到同样.10dB/SSIM/6场景标准：不支持“清空Adam必然有害”。
- 其余如实报告不确定或混合结果。1000步无差别不能排除3000步后差异；即使KEEP较好，也不能把38全部退化唯一归因Adam，因为38还改变日程/微批/噪声。

## 有效性与可恢复性

CPU先检查G6来源SHA6d4946a5f9963ddb1d142b5f4a97f18d0eedf724769aab4b414997a15a33322f、旧Adam参数顺序/436状态及超参/step3000、全新RESET为空，科学与代码清单锁定。KEEP/RESET权重逐张量相同且独立存储；实际输入和noise配对，初始输出及梯度相同。同Adam状态时更新应逐比特相同；真实两臂条件保存/恢复Adam、权重、RNG、日程游标并逐比特重放下一步。全部预检更新丢弃，固定先验始终无梯度且指纹不变；训练与最大整图资源实际预检。

逐100步保存last；100/300/1000固定终点权重保留，日志连续。异常保留源码/失败/状态，只修同协议执行问题，不重置已执行训练。两臂1000步、所有固定评价、summary、独立CPU检查和不含自我覆盖回执的服务器哈希归档齐全才称诊断完成。

全部数据、权重、逐图指标、日志、图像留服务器，本机仅文字和自编源码。旧38及其补充归档不覆盖、不恢复。局部探针与最终64都保留原872索引及evaluation_seed2026/validation随机键；不将子集序号当原索引。原G6 checkpoint未存原完整RNG，按既有逐步种子规则确定新步随机量；KEEP准确称继承Adam，不冒充恢复所有未保存运行状态。
