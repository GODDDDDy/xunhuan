## A. 为什么现在要做这项验证？（研究背景与演变）

### A1. 用户最初真正想研究的是什么

当前研究方向是**偏振辅助反射去除**：利用混合RGB图像与四角度偏振观测，从反射/透射混合场景中恢复透射层。R2P在已有去反射主干（项目内含PolarFree路径）上探索**两轮恢复/循环纠错**：第一轮先恢复一个初始结果，第二轮利用第一轮留下的信息，修正第一轮没有处理好或处理错误的内容。

用户最初强调的不是“产生候选后如何给它打分、选择修改幅度”，而是：

> **第一轮已经产生恢复结果和质量置信度，那么能否让这些质量信息在第二轮的生成过程中起作用，使网络更好地恢复残余反射、修复遗漏，同时尽量不破坏第一轮已恢复好的区域？**

换言之，用户最关心的是**confidence-guided restoration / 质量引导的候选生成**，而不是必须把所有创新集中在**post-hoc acceptance / 事后接受门控**。后者可以保留，但不是本次验证的前提。

请不要把待证假设简化为“C与T1误差是否相关”。质量估计有信息价值和**质量估计是否改善第二轮的生成结果**，属于两层不同问题。

### A2. 当前R2P大致怎样工作（概念图，必须由你对照当前代码确认）

```text
原始混合RGB I + 偏振观测 P0
            │
     第一轮偏振增强/去反射
            ↓
   第一轮恢复 T1 + 多尺度特征 F1
            │
   质量头 H 输出误差尺度 b
            ↓
      C = exp(-b/tau)
            │
      跨轮反馈/状态 Z（及可能存在的Q）
            │
   第二轮偏振增强 + 任务特征融合
            │
    第二轮修正量 Δ / 候选 U = T1 + Δ
            │
    【另一问题】M决定接受多少修正
            ↓
       T2 = T1 + M⊙Δ
```

**区分各对象，避免研究问题错位：**

| 对象 | 在本项目中主要扮演的角色 | 本次实验是否是研究主体 |
|---|---|---|
| `T1` | 第一轮RGB透射恢复 | 基准输出，应在公平比较中保持一致 |
| `F1` | 第一轮多尺度任务特征 | 可能向第二轮提供上下文，需控制/审计 |
| `b / C` | 第一轮质量头H预测的误差尺度与质量分数；`C`大通常表示预计误差较小 | **核心待检验因素** |
| `Z / context['state']` | 跨轮信息载体，可能融合T1、F1、偏振和置信线索；Z是汇报抽象，不一定是代码中的同名张量 | 重点审计置信信号经此处怎样影响U |
| `Q / error_guidance` | 第21组加入的修复需求引导（不要与第19组LocalAcceptance的Need混同） | **重要潜在混杂路径**，不能忘掉其对b/C的使用 |

### A3. 为什么后来会偏向研究Need/Benefit和M

此前实验观察到第二轮候选**部分区域会改善，也会破坏其他区域**。为了在第二轮带来净收益且不损坏T1，项目先后尝试了：

- **质量C引导反馈**：估计T1可靠性，用作第二轮条件输入/特征调制；其排序信息不等于纠错收益。
- **第19组LocalAcceptance（习惯上称“第二代”）**：用Need与Benefit判断局部是否需要修、完整候选是否有益，按启发式公式产生连续权重M，再决定接受多少Δ。
- **第20—22组动作成本判断（习惯上称“第三代”）**：预测接受0.25、0.5、1倍修正量后的MSE变化，选择动作并进行风险阈值校准。

用户与ChatGPT讨论后的结论：**第二代与第三代不是通过严格公平实验已证明逐代提升的体系，而是为解决错误修改提出的两种不同尝试。** 不应反向把最初课题定义为“训练更好的M”。

### A5. 为什么已有实验没有真正回答用户最初假设

现有讨论与抽查源码发现至少四个证据缺口：

1. **C进入模型不等于C有收益。** `C`被拼接或乘到特征上，不能证明模型实际有效利用了“哪里的T1可靠”这类空间信息。
2. **大多数历史机制检查强调门控后T2，不一定直接评价未门控U。** 特别是M=0时，T2会严格等于T1，即便U发生变化；因此T2相同不能用来判断C是否影响了U。
3. **旧C=0/C=1干预未必覆盖全部生成路径。** 归档代码中`study.py`的`confidence_zero/one`主要改的是送入某些通路的`gate`，而`error_guidance(Q)`仍可能拿到原始`b,c`。这属于有待Codex核实的具体旁路问题。
4. **尚未找到/确认具有严格可比条件的“生成器训练使用真实C vs 不使用C”的正式消融。** 如果Codex从完整实验记录发现已经做过合格对照，请直接列出证据，**不要重复跑实验**。

所以，当前最准确的状态是：

> **C有一定的第一轮质量排序能力；C参与第二轮生成的信息通路已经存在；但目前可见证据不足以证明“C的空间质量信息使第二轮候选U变得更好”。**

这也不意味着C必然无用，可能是C表达目标不足、特征融合方式不合适、训练没有利用好、已有实验的评价被M掩盖，或者上述认识本身有误。**请你去核查，而不是直接挑一个理由继续加模块。**

## B. 用户真正希望验证的研究问题与边界

### B1. 第一优先级：确认“C有没有真正改善候选生成”

研究假设（可被否证）：

> 当其余主要因素保持可比时，第一轮的真实质量置信图C能够作为第二轮的**有效条件信息**，使生成的未门控候选U，相对于不使用该空间质量信息的方案获得更可靠的去反射恢复（至少在独立验证场景的PSNR与SSIM上提供可检验的收益）。

用户不要求预设H1成立，也不要求必须保留后处理M。**这一次首先研究“生成”，不是“选择”。**

### B2. 需要区分的四种研究结论

1. **C是否蕴含T1质量线索？** 既有质量头相关性可提供初步回答，但这只是上游表征能力。
2. **当前已经训练好的模型是否实际使用C？** 通过只在推理阶段改变C、观察U变化来诊断，属于当前模型依赖性分析。
3. **准确的空间质量信息是否比常数/错位信息更有用？** 同一已训练模型中可做空间打乱等干预，但可能有分布外效应。
4. **训练时使用真实C是否能获得优于不使用C的生成器？** 原则上需要同起点、同预算训练消融，属于本次核心因果证据；应由Codex根据项目现状判断是否必要、可行、怎样公平。

四者不能相互替代。尤其**“U对C敏感”不等于“C训练带来收益”**；反之，固定模型强干预不敏感，也不足以否定C的所有潜力。

### B3. 特别不希望被带偏的三个方向

- 不要把主要资源继续投入“怎么把四分之一/二分之一/全部修正的收益Spearman提高”，除非能够证明这项工作是检验C→U所必需。

- 不要为了使实验呈正收益而临时更改基线、评价、训练起点、数据划分或条件控制。

### 1. 待检验的问题和假设

#### 1.1 主要研究问题

第一轮已经输出 `T1`、多尺度特征 `F1` 和质量估计 `b`，构造 `C=exp(-b/tau)`。当前 `C` 通过第二轮偏振增强器、跨轮特征反馈、状态调制和 RGB 残差头参与第二轮候选 `U` 的生成。

**要验证的不是 C 有没有进入代码，而是其所携带的空间质量信息是否改善了 U。**

#### 1.2 假设

- **H0（零假设）**：在控制第一轮、模型容量、训练预算及其余输入后，真实空间质量置信度并未带来稳定的候选恢复增益。
- **H1（研究假设）**：真实 C 的空间质量信息能比无空间质量条件的对照生成更好的 U，在跨场景验证中带来具有实际意义的 PSNR 改善，并且 SSIM 不出现系统性退化。

主要比较的是 `U_realC` 和 `U_noC`，不是 `T2_realC` 和 `T2_noC`。

#### 1.3 评价公式

对每张图像 `i`，使用仓库**已有的官方 PSNR/SSIM 计算实现**，避免评价口径变更：

```text
gain_i(condition) = PSNR(U_i(condition), GT_i) - PSNR(T1_i, GT_i)
paired_diff_i    = PSNR(U_i(realC), GT_i) - PSNR(U_i(control), GT_i)
```

主评价是 `paired_diff_i` 在固定验证集上的逐图均值、场景等权均值及各场景方向；辅以 SSIM 的对应差异。PSNR 的逐图差值、全数据像素 MSE 差值、由平均 MSE 得到的 PSNR 不是同一个统计量，不得混用。

### 4. 阶段A：固定模型，不训练，检验 C 是否对 U 有实际作用

#### 4.1 基础原则

同一 checkpoint、同一输入图像、同一训练后参数、同一随机流；仅替换**从第一轮质量头流入第二轮生成链路的条件信号**。所有条件都必须输出完整 `U`；不得让 M 影响任何 U 的评价。

**主要实验条件**：

| ID | 条件 | 目的 | 控制要求 |
|---|---|---|---|
| A0 | `realC`：原样使用预测 `b,c` | 正常基线 | 所有生成路径保持原样 |
| A1 | `constant-quality`：用训练集校准的固定常数替换 `b,c` | 移除第一轮质量头输出的显式空间信息 | 所有通往 U 的质量头路径都改为常数；其余网络权重、通道、计算量不变 |
| A2 | `shuffled-quality`：在同一图像内对 `b,c` 作**相同**的确定性空间置乱 | 保留分数分布，破坏位置和质量对应关系 | 保证 `b/c` 配对及 `c=exp(-b/tau)`；不跨样本传播信息 |

可选诊断 `C0/C1` 只能作为强干预的补充，**不作为“有C vs 无C”的正式证明**，因为 0/1 可能不在训练分布内，并且 `b=-tau*log(c)` 在 `c=0` 时不可用。

#### 4.2 条件构造规范

1. **`b_pred,c_pred` 始终保留**供审计、置信度准确性统计，不改质量头权重或第一轮输出。另构造 `b_cond,c_cond` 专供第二轮生成。C/B 的原始关系为 `c_pred=exp(-b_pred/tau)`，请遵循来源代码的数值精度。
2. `constant-quality`：仅使用**训练集**中固定抽样估计一个正的 `b0`（若已有预锁定标定常数可复用，须说明来源），令 `c0=exp(-b0/tau)`。两者均以对应张量形状广播；**不是逐张图像的均值**，避免泄露图像级质量强弱。禁止从验证/测试 GT 或结果反推 `b0`。
3. `shuffled-quality`：在原预测 `b` 的空间网格上使用由固定 seed + 稳定 sample_id 哈希生成的每图独立置乱，先置乱 `b`，再以公式计算 `c`，或对二者使用同一置乱索引；所有尺度采用同一基础置乱后再插值。若图上仅一个空间单元或置乱后实质不变须记录。
4. 同步替换 `study.recurrent_forward` 中所有送入候选生成的相关质量变量：`gate/effective`、`feedback.make_context` 内条件、`TaskAdapter`、`feedback.fuse/correct`、`error_guidance(Q)` 中的 `b/c` 及其注入状态等。**不得只替换其中一路**。保留独立的 `b_pred/c_pred` 供指标与记录；`Q` 仍由模型自己推理，不能输入 GT。
5. `M` / 事后判断网络**不得参与主结果**；若它仍因旧函数接口被计算，需要验证它不反向改变 U。可以另行记录但不作为主要评价。
6. 在固定 checkpoint 上即使 A1/A2 的指标下降，也只能说明“当前模型**使用/依赖**特定质量条件”，不能证明“使用真实C训练带来增益”；A1/A2 是潜在**分布外干预**。

### 6. 必须避免的常见误判

1. **用T2代替U评价C**：若M全部拒绝，T2必然等于T1，会得出虚假的“C没有用”。
2. **只修改一个`gate`变量**：Q仍读取原始`b,c`，存在旁路泄漏；旧C0/C1实验不能作为完全去C对照。
3. **只置常数C但保留原始b**：同样不是完整移除质量头条件。
4. **只在使用realC训练的模型上推理时改为noC**：只能说明固定网络敏感性，不等于公平训练消融。
5. **把平均权重或置信度排序相关性当作恢复增益**：C和T1误差的Spearman有信息，不代表U的PSNR提高。
6. **把单张图GT Oracle上界当作可部署收益**：推理没有GT；本协议不做Oracle挑动作。
7. **重新训练第一轮**：会混淆置信度贡献和T1起点变化。第一轮必须冻结并通过哈希核验。
8. **按测试集挑实验条件**：本协议不允许用测试结果挑模型、筛选场景、设置阈值或改变训练预算。
9. **把局部质量差视作修正必然正确**：低C提示可能恢复不好，不能确定某次Δ朝向GT。
